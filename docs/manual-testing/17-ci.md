# #17: GitHub Actions CI

**Issue:** https://github.com/yskartheek/BoothConnect/issues/17
**What changed:**

- New workflow `.github/workflows/ci.yml`. It runs on every pull request, on
  pushes to `main`, and on demand (**Actions → CI → Run workflow**).
- Five jobs:

  | Job                  | What it runs                                                                                       | Runs when these change                      |
  | -------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------- |
  | Detect changes       | Decides which of the jobs below run                                                                | always                                      |
  | JS                   | `pnpm install` (cached), `format:check`, then lint, typecheck, test and build through Turborepo    | API, admin web, packages, root config, docs |
  | API integration      | `pnpm --filter api test:int` against Postgres 16 and Redis 7 service containers                    | API, ESLint config, root config             |
  | Admin web end-to-end | Playwright smoke test on the production build; uploads the report if it fails                      | admin web, packages, root config            |
  | Mobile               | `flutter pub get`, `dart format --set-exit-if-changed`, `flutter analyze`, `flutter test` (3.47.5) | `apps/mobile`, the workflow itself          |

  A job that isn't needed shows as **skipped**, which GitHub treats as passing.
  Pushes to `main` always run every job.

- New API integration test (`apps/api/test/health.int-spec.ts`) and script
  `pnpm --filter api test:int`. It found a real bug: right after the API
  started, `/v1/health` reported Redis as down until the connection was
  ready. That's fixed in `apps/api/src/health/redis.check.ts`.

## Steps

1. Open this PR on GitHub and click the **Checks** tab.
   **Expect:** a **CI** workflow with all five jobs green. Because this PR
   touches the API, the web app and the workflow, none of them is skipped.
2. Open the **JS** job and expand **Run pnpm turbo run lint typecheck test
   build ...**.
   **Expect:** `Tasks: ... successful` at the end.
3. Optional: run the new integration test locally:
   ```powershell
   pnpm infra:up
   pnpm --filter api test:int
   ```
   **Expect:** `Tests: 1 passed, 1 total`.
4. Optional: see CI turn red. On a scratch branch based on this one, break
   something small, for example change `'BoothConnect Admin'` to
   `'Wrong title'` in `apps/admin-web/components/welcome-panel.test.tsx`, push,
   and open a draft PR.
   **Expect:** the **JS** job fails at the test step, and the PR shows
   "Some checks were not successful". Close the draft PR and delete the branch
   afterwards.

## Pass criteria

- Step 1 shows all jobs green.

## Known issues and notes

- **The stacked PRs below this one (#83–#88) don't run CI**, because they
  don't contain the workflow file yet. Once this PR is merged, CI runs on
  every later PR. To check an older branch, merge `main` into it after this
  lands.
- **Making CI required:** under **Settings → Branches → Branch protection
  rules** (or **Rulesets**) for `main`, add the CI jobs as required status
  checks. Skipped jobs count as passing, so path filtering doesn't block
  merges.
- **Versions are pinned where they matter:** Node from `.nvmrc` (24), pnpm
  from `package.json` (10.33.0), Flutter 3.47.5 in the workflow's
  `FLUTTER_VERSION`. Update the workflow when you upgrade Flutter.
- **The Android and iOS builds aren't part of CI yet.** They're slow and need
  signing; they can come with the release work.
