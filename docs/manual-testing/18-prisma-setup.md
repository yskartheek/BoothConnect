# #18: Prisma with UUIDv7 IDs and timestamptz conventions

**Issue:** https://github.com/yskartheek/BoothConnect/issues/18
**What changed:**

- Prisma 7.10 in `apps/api`: `prisma/schema.prisma` (no tables yet),
  `prisma.config.ts`, and a global `PrismaService` using the PostgreSQL
  adapter. The client is generated automatically on `pnpm install`.
- A baseline migration that sets the database's time zone to UTC
- Conventions, documented in `apps/api/README.md`: UUIDv7 IDs generated by
  Prisma, `timestamptz` for every date/time, snake_case table names
- Scripts: `db:deploy`, `db:migrate`, `db:reset`, `db:seed`, `db:studio`,
  `db:generate`
- `/v1/health` now checks the database through Prisma (the temporary `pg`
  pool is gone)
- CI applies the migrations before the API integration tests

## Steps

1. Check out the branch, install, and start the services:
   ```powershell
   git checkout claude/issue-18-prisma-setup
   pnpm install --frozen-lockfile
   pnpm infra:up
   ```
   **Expect:** the install log includes `Generated Prisma Client (7.10.0)`.
2. Apply the migrations:
   ```powershell
   pnpm --filter api db:deploy
   ```
   **Expect:** `20260927000000_init` is listed, then `All migrations have been
successfully applied.` Running it again says `No pending migrations to apply.`
3. Check the time zone:
   ```powershell
   docker compose -f infra/docker-compose.yml exec postgres psql -U boothconnect -c "show timezone;"
   ```
   **Expect:** `UTC`.
4. Try reset and seed:
   ```powershell
   pnpm --filter api db:reset
   ```
   **Expect:** Prisma drops the database, re-applies the migration, and runs
   the seed, which prints `Nothing to seed yet ...` (the real seed data comes
   in #26).
5. Run the tests:
   ```powershell
   pnpm --filter api test
   pnpm --filter api test:int
   ```
   **Expect:** `21 passed` and `3 passed`.
6. Start the API (`pnpm --filter api dev`) and open
   http://localhost:4000/v1/health.
   **Expect:** `"database":{"status":"up"...}` as before.
7. Optional: `pnpm --filter api db:studio` opens Prisma Studio in the browser.
   There are no tables yet.

## Pass criteria

- Steps 2–6 give the expected results.

## Known issues and notes

- **`db:reset` deletes all local data.** It's only for development.
- **Prisma 7 no longer reads `.env` files by itself;** `prisma.config.ts`
  loads the same `.env` files as the API.
- **The first `pnpm install` downloads Prisma's migration engine** (about
  20 MB) from Prisma's servers.
- **Prisma is pinned to 7.10.0.** npm's `latest` tag for the `prisma` package
  currently points at an 8.0 release candidate, which we don't use yet.
