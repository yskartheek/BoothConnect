# #56: Shared strings package (English + Telugu)

**Issue:** https://github.com/yskartheek/BoothConnect/issues/56
**What changed:**

- New package `packages/i18n` holds every word the apps show, in **English**
  and **Telugu**, in two files: `locales/en.json` and `locales/te.json`
- Shared words used by both apps: visit outcomes ("Met the family", "No one
  home" …), upload states ("On phone", "Uploading", "Uploaded", "Choose
  value", "Not uploaded"), one message per API error code, and the caste
  consent notice
- A script writes the Flutter app's language files (`app_en.arb`,
  `app_te.arb`) and the admin web's (`en.json`, `te.json`) from those two files
- The mobile app now speaks Telugu when the phone is set to Telugu
- The admin web reads its words from the package too (still English only)
- **CI fails if a word is missing in any language**, or if the Flutter
  language files weren't regenerated

## Steps

1. Check out the branch and install:
   ```powershell
   git checkout claude/issue-56-i18n
   pnpm install --frozen-lockfile
   ```
2. Run the missing-translation check:
   ```powershell
   pnpm --filter @boothconnect/i18n check
   ```
   **Expect:** `All keys translated: en (58), te (58).`
3. See it catch a missing translation. Open
   `packages/i18n/locales/te.json`, delete the line with
   `"syncState.failed"`, save, and run step 2 again.
   **Expect:** `✖ te: missing translation for "syncState.failed"` and an
   error. Undo it:
   ```powershell
   git checkout -- packages/i18n/locales/te.json
   ```
4. Run all the checks:
   ```powershell
   pnpm --filter @boothconnect/i18n test
   pnpm --filter mobile test
   pnpm --filter admin-web test
   ```
   **Expect:** `Mobile ARB files are up to date.` and `# fail 0` for the
   package, `All tests passed!` (18 tests) for mobile, and all Vitest tests
   passing for the admin web.
5. Mobile app in Telugu. Start the Android emulator and run the app:
   ```powershell
   pnpm --filter mobile start
   ```
   Then on the emulator: **Settings → System → Languages (→ System languages) → Add a language →
   తెలుగు**, and drag it to the top.
   **Expect:** the home screen reads **BoothConnect కు స్వాగతం**. Move English
   back to the top and it reads **Welcome to BoothConnect**.
6. Admin web still shows the same English text:
   ```powershell
   pnpm --filter admin-web dev
   ```
   **Expect:** http://localhost:3000 looks exactly as before ("BoothConnect
   Admin", "Appearance", "Theme" …).
7. Optional: review the Telugu. Open `packages/i18n/locales/te.json` next to
   `en.json`. The descriptions in `en.json` (the `"@…"` lines) explain each
   string.

## Pass criteria

- Step 2 passes and step 3 shows the check failing on a missing translation.
- Step 4 passes, step 5 switches the app's language, and step 6 is
  unchanged.

## Known issues and notes

- **The Telugu is a draft** written by Claude. Please have a native speaker
  review it before real use, especially the voter-facing texts.
- **The consent notice is draft wording in both languages.** Spec §22
  requires legal review before it is used with voters.
- **Why Telugu?** The issue asked for a placeholder regional language
  (`xx`). A made-up code would break Flutter's own translated widgets, and
  the mockups show తెలుగు, so Telugu is the placeholder. Adding Hindi or
  another language is one more file (see `packages/i18n/README.md`).
- **The admin web is English only for now.** Its Telugu file is generated,
  but there's no language switch yet. The mobile app follows the phone's
  language; an in-app switch (spec §15) comes later.
- **Only the home screens use the strings so far.** Visit outcomes, upload
  states, errors and consent are ready in both apps for the screens that
  come next.
